# Git hook と CI で品質検査を共有する

- **ステータス**: 承認
- **決定日**: 2026-10-20

## 背景

品質検査の手順を Git hook と CI に個別に記述すると、検査内容の追加や変更時に両方を更新する必要がある。Git hook の生成・既存
hook の保護を独自スクリプトで管理すると、Git hook の追加や導入方式の変更に応じて保守が必要になる。Codex のファイル編集
hook は、変更対象を特定できる編集では整形できるが、Bash や MCP 経由の編集では対象を安全に特定できない場合がある。

## 決定

- push 前と CI で同じ品質検査タスクを実行する。
- Git hook は Lefthook で管理し、初回セットアップ時に明示的にインストールする。依存パッケージの postinstall
  にインストールを任せず、既存の独自 hook は上書きしない。
- 編集対象が明らかな場合だけ自動整形し、それ以外の変更は読み取り専用で検査する。
- 検証済みの同一内容を再度検査しないよう、一時領域に成功結果を保存する。
- Codex hook の対象ファイル収集と書き込み範囲は Codex の編集イベントに依存するため、汎用 Git hook manager や staged-file
  linter に置き換えず Node.js 標準 API で実装する。Lefthook の Codex 連携は beta のため利用しない。

## 検討した選択肢

| 選択肢                                          | 評価                                                                     |
|-------------------------------------------------|--------------------------------------------------------------------------|
| **Lefthook と Node.js 標準 API を組み合わせる** | Git hook 管理を Lefthook に任せ、Codex hook は必要な対象収集を実装できる |

## 結果

- **良い点**
    - Git hook と CI の検査手順が一致し、どちらかへの追加漏れを減らせる。
    - 変更対象を特定できない編集経路では、自動整形による既存差分の変更を避けられる。
    - Lefthook が Git hook の生成と管理を担い、セットアップは依存パッケージの postinstall 実行に依存しない。
- **注意点**
    - hook はローカルで任意に無効化できるため、CI を必須の検査境界として維持する。
