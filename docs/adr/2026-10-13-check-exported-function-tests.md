# export 関数の直接テストを静的に確認する

- **ステータス**: 承認
- **日付**: 2026-10-13

## 背景

export 関数のテスト漏れを防ぎたい。一般的な関数カバレッジは内部関数や間接呼び出しも集計するため、export
関数を直接テストする方針とは一致しない。

## 決定

- export する関数ごとに、振る舞いを直接検証するテストを書く。
- 既存の TypeScript Compiler API を使って export 関数とテスト中の呼び出しを対応付け、`mise run lint` で確認する。
- 対象は `src/` と `scripts/` の TypeScript モジュールで、宣言ファイル、テスト、生成物、依存パッケージは含めない。Astro
  ファイルの解析は対象外とする。
- `tests/` 以下の `*.test.ts` の `node:test` の `test` または `it` に渡すインラインのコールバック内に、対象関数の呼び出しがあることを確認する。明示的な
  skip または todo は含めない。
- 別名 import、namespace import、default export、関数を格納した変数、再 export に対応する。同じ関数の再 export は一度の直接テストでよい。

## 結果

- import しただけの関数や、テスト本体の外でのみ呼び出す関数を検出できる。
- 静的チェックは、呼び出しの実行、到達可能性、アサーションの有無や妥当性を保証しない。テストの実行とレビューで確認する。
- テストの共通ヘルパー内だけで対象関数を呼ぶ場合や、関数を引数として渡す場合は直接呼び出しとして数えない。
