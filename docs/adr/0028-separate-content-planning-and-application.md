# 0028. コンテンツ同期の計画と適用を分ける

- **ステータス**: 承認
- **日付**: 2026-10-13

## 背景

外部コンテンツの同期ライブラリに、URL 判定、保存データ、保持件数の選定、RSS・リンク通信、変更適用が集まっている。
選定を検証するテストにも一時ファイルや通信の差し替えが必要で、変更計画とファイル操作の境界も追いにくい。

## 決定

- 同期・削除の処理を、HTTP と処理の組み立てを担う `external-content.ts`、URL・索引・保持件数・変更計画を担う `external-content-planning.ts`、YAML 読込・検証とファイル操作を担う `external-content-files.ts` に分ける。
- `external-content.ts` は既存の利用箇所との互換性を保つ facade とする。計画関数は通信・ファイルアクセスを行わず、保存項目と RSS またはリンク確認結果を入力として決定的な計画を返す。
- 同期・削除の計画は、実行前にすべての対象パスと衝突を検証する。dry-run は通常実行と同じ計画を返し、通常実行はその計画を適用する。
- CLI へ渡す変更・削除結果は、保存データの内部型ではなく、操作に必要な項目を持つ名前付き DTO とする。
- ファイル更新は対象と同じディレクトリに一時ファイルを書き、rename で置き換える。複数ファイル全体の rollback は保証せず、途中失敗後は保存済みデータを読み直して計画を作り直す。
- URL の比較ではフラグメントを除き、クエリを保持する。公開日が同じ項目は正規化 URL の順で決める。既存 `types` の保持、JST の日付、保存済み項目だけを削除対象にする方針は維持する。

## 結果

- 純粋な選定・計画を通信や一時ディレクトリなしでテストできる。
- 対象検証の失敗では、ファイル変更を始めない。
- 各ファイルの更新は原子的だが、複数ファイルの途中失敗では一部変更が残る。再実行は再読込・再計画により収束させる。
