# Knip で未使用コードを検出する

- **ステータス**: 承認
- **日付**: 2026-10-20

## 背景

未使用のファイル、依存パッケージ、export は、呼び出し関係や責務を変更した後も残ることがある。Lint や型チェックだけでは、プロジェクト全体の利用関係を確認できない。

## 決定

- Knip で未使用ファイル、依存パッケージ、export を検出する。
- 通常コードと本番コードを別々に解析し、テストからしか使われない export も把握する。
- Astro や CLI など、フレームワークや実行環境が利用する入口を解析対象として扱う。
- 専用の未使用 export 解析は重複させない。export 関数の直接テストの静的確認は既存の仕組みを維持する。
- フレームワーク固有の解析漏れは、理由を示して影響範囲を限定する。

## 結果

- production 解析では、フレームワーク管理の構成ファイルを通常の import グラフから除外する場合がある。除外で生じる検出漏れには、通常解析での検出を保ちながら、理由を明示した限定的な例外を設ける。
- import 関係だけでは表れない、フレームワークや運用環境の入口は設定で明示する必要がある。
- 静的解析で意図的に維持するコードは、理由を添えて対象を限定する。
