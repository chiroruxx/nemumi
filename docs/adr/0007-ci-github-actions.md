# 0007. CI に GitHub Actions を採用する

- **ステータス**: 承認
- **日付**: 2026-09-24

## 背景

Cloudflare Workers Builds（[ADR 0001](0001-hosting-cloudflare-workers.md)）はビルドとデプロイのみを行い、Lint や型チェックは実行しない。
`main` はルールセットで保護しており、PR のマージ前に必須のステータスチェックを通す運用としたい。
リポジトリは公開のため、GitHub Actions を無料で利用できる。

## 決定

CI には GitHub Actions を採用し、`.github/workflows/ci.yml` に定義する。

- PR と `main` へのプッシュで、Lint（`biome ci`）・型チェック（`pnpm check`）・ビルド（`pnpm build`）を実行する。
- ツールのインストールには `jdx/mise-action` を使い、ローカルと同じ `.node-version` と `mise.toml`
  のバージョンを使う（[ADR 0002](0002-tool-version-management-mise.md)）。
- 外部の Action はコミット SHA で固定し、コメントにバージョンを併記する。
- ワークフローの権限は `contents: read` のみとする。

デプロイは引き続き Workers Builds が行い、GitHub Actions からはデプロイしない。

## 検討した選択肢

| 選択肢                                  | 評価                                                                                   |
|-----------------------------------------|----------------------------------------------------------------------------------------|
| **GitHub Actions**                      | 公開リポジトリでは無料。ルールセットの必須チェックと連携でき、将来の定期実行にも使える |
| Workers Builds のビルドコマンドに含める | 設定は増えないが、デプロイ前提のビルドと混ざり、結果が PR で分かりにくい               |
| CI を置かない                           | ローカルと hook のみに頼るため、実行漏れを防げない                                     |

### ツールのインストール方法

| 選択肢                                 | 評価                                                                  |
|----------------------------------------|-----------------------------------------------------------------------|
| **jdx/mise-action**                    | ローカルと同じ設定ファイルを読むため、バージョンの指定が 1 か所で済む |
| actions/setup-node + pnpm/action-setup | 広く使われているが、pnpm のバージョンを別途指定する必要がある         |

## 結果

- **良い点**
    - Lint・型チェック・ビルドの失敗を、マージ前に PR 上で検出できる。
    - 将来、RSS 取得のための定期再ビルドなども同じ仕組みで追加できる。
- **注意点**
    - Action をコミット SHA で固定しているため、更新は手動か、Step 8 で導入する依存更新ツールで行う。
    - ルールセットの必須チェックには、ジョブ名 `Lint, type check and build` を指定する。ジョブ名を変えた場合はルールセットも更新する。
