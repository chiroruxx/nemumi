# 不要なブランチの整理

削除対象はローカルブランチと、`git worktree prune` による不要な worktree 登録のみ。
リモートブランチ、worktree のディレクトリ、作業ファイルは削除しない。
PR、マージ状態、コミットの取り込みや未 push の追加コミットは確認しない。
未マージでリモートから削除されたブランチも、以下の条件を満たせば削除対象とする。
追加の指示なしでこの skill が呼び出された場合は、候補一覧に対する確認を求めず、条件を満たすブランチの削除まで行う。
「調査だけ」「確認してから削除」などの明示的な指示がある場合は、その指示を優先する。

## 削除候補の定義

次の条件をすべて満たすブランチを候補にする。
- リモートブランチを追跡する upstream が設定されている。
- 対応するリモートの fetch と prune が成功し、upstream のリモート追跡参照が削除済み（gone）である。
- `main`、既定ブランチ、リポジトリやユーザーが保護対象としているブランチではない。
- いずれの worktree でもチェックアウトされていない。

upstream 未設定、ローカルブランチを upstream とするもの、リモートが削除済みまたは取得に失敗したものは残す。
リモートブランチが残っている場合も削除しない。進行中 PR の head・base は保護条件にしない。

## 開始時

削除を依頼された場合は、候補の調査前に `git switch main` でローカルの `main` に切り替える。
既に `main` にいる場合は切り替え不要。切り替え前のブランチは、それだけを理由に保護しない。
- 切り替え前に作業ツリーと index を確認する。未コミットの変更（未追跡ファイルを含む）や進行中の merge・rebase などがあれば、理由を報告して停止する。
- ローカルの `main` が存在しない場合や、別の worktree が `main` を使用中の場合も停止する。
  ブランチの新規作成や強制切り替えで回避しない。
- 切り替えに失敗した場合は停止する。stash、reset、worktree の削除で回避しない。
- `main` に切り替えた後（既に `main` の場合も含む）、`git pull --ff-only` で最新に追従する。
  取得に失敗した場合や fast-forward できない場合は理由を報告して停止し、merge や rebase で回避しない。
- pull の成功後、候補の調査前に `git worktree prune` を実行する。
  Git の標準の期限・ロック判定に従い、`--expire now` や unlock で対象を広げない。
  失敗した場合は理由を報告して停止する。成功後に worktree 一覧を取得し直し、残っている登録のブランチを保護する。
- 候補の調査だけを依頼された場合は、切り替え、pull、`git worktree prune` を行わず、その時点で worktree にチェックアウト中のブランチを保護する。

## 調査と提示

1. 対象リポジトリ、既定ブランチ、ローカルブランチごとの upstream と対応するリモートを確認する。
   リモート名を `origin` と仮定せず、同名ブランチの有無ではなく設定された upstream を使う。
2. upstream に対応するリモートごとに `git fetch --prune -- <remote>` を実行する。
   prune はリモート追跡参照の整理に限り、タグやローカルブランチを prune する設定の場合は実行せず理由を報告する。
   リモートごとの成否を記録し、失敗したリモートについて古い gone 情報から削除候補を作らない。
3. `git for-each-ref` の upstream・upstream:track と `git worktree list --porcelain` などで、
   gone、先端コミット ID、worktree の使用状況、保護条件を確認する。
   fetch の対象外の参照など、リモートの削除により gone になったと確認できないものは残す。
4. 削除候補と残すブランチを理由付きで提示する。候補にはブランチ名、先端コミット ID、upstream を示し、
   マージ状態や未 push コミットの有無によらず `-D` で削除することを明記する。
   既定では確認を求めず削除へ進む。確認してから削除するよう明示された場合のみ、一覧に対する了承を待つ。
   候補の調査だけを依頼された場合は、一覧の提示で完了する。

## 削除

- 削除直前に対応リモートの fetch と prune を再実行し、先端コミット ID、upstream の設定と gone、worktree の使用状況、保護条件を再確認する。
  取得に失敗した場合や一覧提示後に条件が変わった場合は、そのブランチを対象から外す。
- 条件を満たす候補だけを `git branch -D -- <branch>` で個別に削除する。
  明示的に対象が限定されている場合はその範囲に限り、確認が指示されている場合は了承済みの候補に限る。ブランチ名は安全にクォートして渡す。
  削除に失敗したブランチは残して理由を報告し、参照の直接削除で回避しない。
- 開始時の `main` への切り替え以外のブランチ切り替え、worktree のディレクトリ削除、stash、reset、設定変更を削除の都合で行わない。
- 完了時に削除できたブランチと先端コミット ID、残したブランチと理由を報告する。
