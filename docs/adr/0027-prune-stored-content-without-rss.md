# 0027. 保存済みコンテンツだけを削除対象にする

- **ステータス**: 承認
- **日付**: 2026-10-13

## 背景

[PR #29](https://github.com/chiroruxx/nemumi/pull/29) はサービスごとの RSS 同期と共通の削除処理を追加する。
PR 内の [ADR 0025](https://github.com/chiroruxx/nemumi/blob/957c922e39d330f99bb5d1abcc42525ffd55a5ac/docs/adr/0025-sync-external-content-from-rss.md) は、
既存データと RSS を統合した公開日順で保持対象を選ぶ一方、削除処理は同期の成功やマージを前提にせず、実行時点の main を整理するとしている。

削除時にも RSS を取得すると、未保存の新規項目が保持件数の枠を消費し、同期失敗や未マージの間に掲載済み項目が削除候補となる。
保存済み記事 20 件より新しい未保存記事 20 件が RSS にある場合、掲載済み記事すべてが削除候補になることを再現した。
また、RSS の障害が保存済み項目の整理にも影響する。
削除に必要なのは、main に保存されている項目の公開日・URL とリンク先の状態である。

同じレビューで、同期後に保持する YAML の項目は Astro Content Collections のスキーマを基準とすることを確認した。
スキーマ外の任意フィールドの保存は必要ないため、計画文書の「その他の手動管理項目は保持」という記述を訂正する。

## 決定

- 削除処理は RSS を取得せず、実行時点の main に保存済みの YAML だけを対象とする。
- 保存済み項目の公開日と比較用 URL でディレクトリごとの保持件数を適用し、上限外の同期対象項目を削除候補にする。
- 上限内の保持対象はリンク先を確認し、失効を確認した項目を削除候補にする。RSS の項目や未マージの同期結果は選定に使わない。
- 対象外の手動データの保護、リンク確認の判定保留、削除後に同一実行で補充しない扱いは ADR 0025 を維持する。
- 同期処理の追加・更新候補は、従来どおり既存データと RSS を照合して選ぶ。同期と削除の選定入力を分ける。
- 同期時に保持するフィールドは Astro Content Collections のスキーマを基準とする。スキーマ外のフィールドは消えてよい。
- 同期対象の `date`・`title`・`url` は RSS から更新し、スキーマ内の既存 `types` は保持する。

この決定は、ADR 0025 の RSS 統合ランキングを削除処理にも適用する部分を置き換える。
同期・削除の実行時刻、サービス別 PR、保持件数など、その他の方針は変更しない。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| **保存済み項目だけで削除対象を選ぶ** | 実行時点の main を直接整理でき、未保存の項目と RSS の障害に影響されない |
| RSS と保存済み項目を統合して削除対象を選ぶ | 未保存の項目が既存項目を押し出すため、同期の成功・マージを前提にしない運用と合わせにくい |

## 結果

- **良い点**
    - 同期・追加と保存済み項目の整理の責務を分けられる。
    - 削除時の RSS 通信が不要になり、RSS 障害中も保存済み項目の上限と失効を確認できる。
    - 保存するフィールドの基準がコンテンツスキーマと一致する。
- **注意点**
    - 同期結果がマージされて初めて、新しい項目や更新した公開日が削除時のランキングに反映される。
    - スキーマ外のフィールドを保持する必要が生じた場合は、先にスキーマと同期の扱いを定義する。
