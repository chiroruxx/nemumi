# 0029. 外部コンテンツの通信実行に時間予算を設ける

- **ステータス**: 承認
- **日付**: 2026-10-13

## 背景

RSS とリンクの取得にはリクエストごとのタイムアウトがあるが、リダイレクトや再試行を含む処理全体の期限はない。Actions のジョブは10分で終了するため、通信に期限がないとジョブ強制終了まで実行レポートを作れず、未確認項目を次回へ安全に残せない。

## 決定

- RSS 取得とリンク確認には、既定8分の共通実行期限を渡す。10分の Actions 制限内に、依存準備・認証・PR 操作の時間を残すため、既定値は8分とする。呼び出し側は実行期限を差し替えられる。
- 個々の HTTP リクエストには従来どおり30秒のタイムアウトを適用し、全体期限とは別の AbortSignal として扱う。
- RSS の応答本文は5 MiBまで、再試行は最大2回とする。ネットワーク例外、429、5xx は待機後に再試行し、`Retry-After` は秒数と HTTP 日付の両方を解釈する。リダイレクト・エラー・リンク状態の応答本文は消費またはキャンセルする。
- リンク確認は最大2件を同時実行し、同一サービスへの HTTP リクエスト開始間隔を既定1秒以上にする。間隔は時計・待機関数とともにテスト時に差し替えられる。
- RSS の XML 解析と `FeedItem` への変換は HTTP から分け、各サービスの固定 fixture でネットワークなしに検証する。
- 削除では、期限までに確認できた削除判定と件数上限の計画だけを適用し、defer・review・未確認項目は保持する。結果には保持・未確認理由と残件数を含める。
- 同期では、新規リンクが defer・review の場合は従来どおり適用前に失敗する。全体期限で未確認が残った場合は、確認済みの変更も部分適用せず、保存済みデータを維持して未確認項目を報告する。
- HTTP 200 の応答がサービス固有の非公開・エラーページかどうかは、実例を確認できるまで HTML 文字列の推測判定を追加しない。

## 結果

- 通信全体が Actions の実行期限より前に終了し、期限時点の未確認項目を結果に残せる。同期結果の `skipped` は追加を見送った項目、削除結果の `skipped` は手動管理項目を表す。
- 個別リクエストのタイムアウト、全体期限、HTTP 状態による defer/review を区別して扱える。
- 期限切れ時の削除は確定済みの安全な計画に限られ、同期は保存済みファイルを変更しない。
