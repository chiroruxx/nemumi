# サイトのタイムゾーンを一元管理する

- **ステータス**: 承認
- **日付**: 2026-10-14

## 背景

サイトの日付は、RSS からの取り込みとページ表示で別々にタイムゾーンを指定している。取り込みは `Asia/Tokyo` に変換する一方、一覧の表示は
UTC で日付を取り出しており、サイトとして日付を扱う基準がコード上で統一されていない。

## 決定

- サイトのタイムゾーンは Node.js が使う `TZ` 環境変数で指定する。ローカル環境ではプロジェクト直下の `.env` に設定し、mise
  が各タスクへ読み込む。Astro は `.env` を読み込む。
- 設定例を `.env.example` に記載し、環境変数がない場合は `Asia/Tokyo` を使う。
- 日時からサイト上の日付を作る処理は `src/config/site-time.ts` の `formatDateInSiteTimeZone` を使う。RSS
  の公開日変換とページの日付表示はこの関数を参照する。
- 日付の変換では `TZ` を `Intl.DateTimeFormat` に明示し、実行環境の既定タイムゾーンには依存しない。

## 結果

- RSS 取得、コンテンツ表示で同じタイムゾーンを使い、実行環境のローカルタイムゾーンによる差を避ける。
- ローカル・CI・Astro ビルドで同じ `TZ` 環境変数を使い、環境別の起動コマンドに値を追加せず設定を管理できる。
- `TZ` が未設定の環境では `Asia/Tokyo` が使われる。
