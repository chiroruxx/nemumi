# 0039. コンテンツ自動処理を直列化してリンク確認を共用する

- **ステータス**: 承認
- **日付**: 2026-10-17

## 背景

同期サービスごとに別の PR を作ると、同じ保存済みデータのリンク削除を複数 PR が含む可能性がある。同期対象外の保存済み URL
は、従来 prune を実行するまで確認されなかった。

## 決定

- Update content は選択された各サービスの同期を1ジョブ内で順番に実行する。全サービス同期の途中で失敗した場合は処理を停止し、後続サービス、リンク確認、PR
  作成を行わない。
- 同期完了後、全コレクションの同期管理コンテンツをリンク確認し、確認できた404・410だけを削除する。手動管理コンテンツは対象にしない。
- Prune content は件数上限による削除を行い、その後、Update content と共通のリンク確認を行う。
- 未確認 URL は保持して報告する。dry-run では削除しない。
- それぞれの workflow は生成した変更を1つの PR にまとめる。手動のサービス選択でも同じ順序と PR を使う。
- この決定は [ADR 0025](0025-sync-external-content-from-rss.md)
  のサービス別同期・失敗サービスを独立して続行する部分、[ADR 0027](0027-prune-stored-content-without-rss.md) の prune
  がリンク確認も行う部分、および [ADR 0036](0036-report-unverified-content-urls.md) の同期で新規候補だけをリンク確認する部分を置き換える。

## 結果

- 更新 workflow は3サービスの同期と全リンク確認を直列で行う。それぞれ最大8分の実行予算を持つため、workflow の上限を40分にする。
- URL の無効確認と削除は同期と prune の両方から共通 CLI を通じて行う。
- 同期途中の失敗では一部の変更が作業環境に残るが、後続処理と PR 作成は停止する。
